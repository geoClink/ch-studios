Overview

The Bakery Co. Platform is a full business operating system for small businesses — five connected surfaces built on a single Supabase (Postgres) backend. It started as a website and admin dashboard. It's now a web platform, a 18-section business dashboard, an iOS employee scheduling app, an iOS point-of-sale, and an iOS customer app — all HTTP clients against the same REST API.

The architecture is multi-tenant from the start. Every table carries a tenant_id, every API route scopes to it, and nothing in the backend is specific to a bakery. The Salon Co. and Sports Bar Co. are next — onboarding a new client is one database row and a frontend deploy.

The Problem

Small businesses run on fragmented tools. A bakery takes custom orders by DM, tracks inventory in a notebook, manages staff schedules by text message, and pays 15–30% commission to DoorDash or Uber Eats to get found online. There's no single source of truth. The owner can't see revenue, labor costs, and inventory in the same place — let alone act on any of it from their phone at 6am.

The goal was to replace that stack with one platform the business owns: direct ordering with zero commission, an admin dashboard that replaces $200–500/month in SaaS tools, an iOS scheduling app that gives managers and staff everything they need on their phones, and a POS that works for in-person sales without a separate system.

Technical Architecture

One Backend, Five Clients

All five surfaces are HTTP clients against the same Express REST API and Supabase database. No special integration layer. An order placed through the iOS customer app, the website, or the POS lands in the same orders table, visible instantly in the admin dashboard.

Multi-Tenant from the Start

Every table carries a tenant_id column. Every API route scopes its queries to the current tenant before any data is read or written. Nothing in the codebase is bakery-specific. The Salon Co. and Sports Bar Co. are next — onboarding is one database row and a frontend deploy.

Supabase Realtime

KnotEmployee uses Supabase Realtime websockets so live clock-in status, new messages, and schedule updates propagate to all connected devices instantly — no polling, no manual refresh.

APNs via Deno Edge Function

Push notifications in KnotEmployee are triggered by Supabase database events. When a row is inserted into the kn_notifications table, a Deno Edge Function fires and delivers the notification through Apple Push Notification Service.

Key Technical Features

Two Stripe Payment Flows

Stripe Elements for customer checkout (confirmCardPayment client-side, order saved only after webhook confirms). Stripe Checkout Sessions for MCP/AI-initiated orders (returns a hosted URL). A single webhook endpoint handles both flows via metadata.source.

MCP Server

A production Model Context Protocol server built with @modelcontextprotocol/sdk. Three tools: get_menu, get_hours, and place_order — which validates stock, builds Stripe line items, and returns a checkout URL. AI assistants can browse the menu and complete a transaction without touching the website.

WebMCP Integration

Shipped the week Google announced WebMCP at I/O 2026. Menu search, hours, and checkout are registered as browser-native AI tools via the W3C WebMCP standard (Chrome 146+). Customers using AI-enhanced browsers can order without leaving a chat interface.

Collaborative Filtering Upsell

Four-level fallback chain for "you might also like" suggestions: real co-purchase frequency from the item_pairs table → manually curated paired_items → time-aware cross-sell (breakfast/lunch/etc) → best sellers. Degrades gracefully for new menu items with no purchase history.

Crumb Rewards Loyalty

Math.floor(total) points per order. Supabase RPC increment_points handles the increment atomically to prevent race conditions on concurrent orders. 100 points = $1 off.

4 Cron Jobs

Daily 8pm summary, weekly Sunday report, unfulfilled order reminder every 2hrs, birthday coupon generation at 8am. Birthday coupons record birthday_coupon_year to prevent duplicate codes across calendar years.

Technical Decisions

Payment-First, Then Save

The Stripe charge is confirmed via webhook before the order is written to the database. If the server crashes between payment and save, Stripe retries webhook delivery until the order is recorded. No phantom orders, no silent failures.

API-Level Auth, Not UI-Level

Hiding a button in the browser isn't security. The admin dashboard checks login state in the UI — but every API route it calls also verifies the JWT server-side. Any HTTP client can call /api/admin/refund directly; the middleware catches it before any data is touched.

Rate Limiting on Checkout Only

Rate limiting is applied specifically to the checkout endpoint, not globally. Repeatedly hitting checkout could trigger Stripe fraud flags and put the merchant account at risk. That endpoint warranted its own stricter limit.

@Observable Over ObservableObject

KnotEmployee uses Swift's @Observable macro (iOS 17+) instead of ObservableObject. Finer-grained observation means only the views that depend on a changed property re-render — critical for a scheduling app where one Realtime event can't ripple through the entire view hierarchy.

Supabase RPC for Points

Loyalty points use a Supabase RPC function instead of a read-then-write pattern. Two orders completing simultaneously against the same customer row would both read the same starting balance and one increment would be lost. The RPC runs atomically inside the database.

Deno for APNs

APNs delivery runs in a Deno Edge Function triggered by a Supabase database event, not inside the Express server. Keeps notification logic decoupled from the web API and eliminates a failure mode where the Node.js process going down silently drops mobile notifications.

Unified Webhook Handler

Two distinct Stripe payment flows — Stripe Elements for direct checkout, Stripe Checkout Sessions for MCP orders — funnel into a single webhook endpoint. The handler branches on metadata.source.

Unified Webhook — server.js
app.post('/webhook', express.raw({ type: 'application/json' }), async (req, res) => {
    const sig = req.headers['stripe-signature'];
    let event;

    try {
        event = stripe.webhooks.constructEvent(req.body, sig, process.env.STRIPE_WEBHOOK_SECRET);
    } catch (err) {
        return res.status(400).send(`Webhook Error: ${err.message}`);
    }

    if (event.type === 'payment_intent.succeeded') {
        const pi = event.data.object;

        if (pi.metadata.source === 'mcp') {
            await fulfillMcpOrder(pi);
        } else {
            await fulfillWebOrder(pi);
        }
    }

    if (event.type === 'invoice.payment_succeeded') {
        await generateSubscriptionOrder(event.data.object);
    }

    res.json({ received: true });
});
